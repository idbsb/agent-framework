# 求职者端白底商业化前端改版设计

## 目标

将现有八页面系统从深色技术演示界面升级为面向求职者的白底商业化 SaaS 产品。改版只调整前端信息架构、视觉样式、展示文案和交互状态，不改变算法、评分、Evidence、真实数据、API 契约或冻结工作簿。

## 用户与表达原则

主要用户是希望了解岗位、分析简历并评估人岗匹配度的求职者。页面文案应回答“我能获得什么帮助、结果意味着什么、下一步可以做什么”，不出现开发环境、适配器、静态回退实现、内部引擎名称、英文产品占位名或页面序号等无关信息。

必要的数据真实性提示继续保留，但改写为用户可理解的说明。系统不得虚构账号、头像、通知、更新时间或运营数据。

## 实施策略

保留现有 React 路由、页面业务状态和 API 调用，在此基础上重构展示层：

1. 在全局样式中建立颜色、间距、圆角、阴影、字号和动效 Design Tokens。
2. 重构 `Layout`、侧栏、移动端导航和顶部页面标题区。
3. 统一卡片、状态提示、按钮、表单、标签、空状态、抽屉和 Evidence 展示。
4. 逐页调整结构和求职者文案，不改变接口输入输出和计算结果。
5. 将 ECharts 统一为白底、浅网格、深灰文字、绿色主序列的商业配置。

不采用纯 CSS 覆盖方案，因为页面文案和信息层级也需要调整；不重写业务页面和后端，以降低回归风险。

## 设计系统

- 页面背景：`#F5F7FA`
- 卡片：`#FFFFFF`
- 侧栏：`#171A21`
- 主色：`#10B981`
- 主色悬停：`#059669`
- 主色浅背景：`#ECFDF5`
- 主文字：`#111827`
- 次级文字：`#6B7280`
- 弱提示：`#9CA3AF`
- 边框：`#E5E7EB`
- 信息、警告、错误：`#3B82F6`、`#F59E0B`、`#EF4444`
- 圆角以 10、12、16px 为主，卡片使用轻阴影，不使用霓虹、发光边框或持续动画。
- 使用系统中文字体栈与 Lucide 图标；交互过渡控制在 150–200ms，并支持 `prefers-reduced-motion`。

## 全局布局

桌面端使用约 240px 固定深色侧栏和浅色主内容区。侧栏展示项目中文名称与“岗位能力图谱与智能匹配平台”副标题，保留现有八项导航和原路由。激活项使用绿色竖线与低透明绿色背景。

顶部栏仅展示当前页面名称、求职者导向说明以及真实可得的系统状态。删除 `TALENT GRAPH`、`MULTI-SOURCE TALENT INTELLIGENCE`、`Evidence-bound AI`、`01 / 08` 等内部或装饰性内容。

768px 左右使用可展开抽屉式导航；内容卡片自适应换行，宽表格只在自身容器滚动。1366×768 与 1920×1080 下主操作均保持可见。

## 八个页面

### 数据驾驶舱

改为“求职数据概览”，保留全部真实指标、重点岗位、热门技能和新岗位候选数据。用白色指标卡和轻量趋势表达替代大面积深色 Hero。

### 岗位分析

突出岗位选择、岗位要求、核心职责和技能分布。技能频率图切换为浅色商业图表；保留真实聚合数据与既有筛选。

### 岗位能力图谱

保留拖拽、缩放、节点点击和 Evidence 查看。图谱采用白色画布、绿色技能节点、蓝色岗位节点、浅灰关系线；详情区改为清晰的侧卡片或抽屉。

### 动态演化

用趋势摘要卡展示核心、增长、新增、稳定、下降技能。数据不可用或样本不足时，使用用户可理解的状态说明，不展示适配器文件名和内部流程。

### 新岗位发现

将候选岗位呈现为机会卡片，保留置信等级、评分、企业数、来源数、技能与完整 Evidence 抽屉。审慎性声明继续保留。

### JD 智能解析

改写为“职位解析”，保持所有输入字段、示例、清空和解析操作。结果区突出标准岗位、岗位匹配强度、技能要求和证据来源，不显示“真实 API”“现场演示”等开发提示。

### 简历智能分析

作为重点求职流程，采用上传/填写区与分析结果区。保留 PDF、DOCX、TXT 上传、8MB 限制、所有文本字段、能力画像与 Evidence；将“CV”等技术占位表达替换为中性求职产品表达。

### 人岗匹配

保留全部表单、综合得分、五维评分、技能差距、优势技能、学习路径和 Evidence。雷达图使用浅灰网格与绿色填充；不在前端重新计算任何分数。

## 数据流与兼容性

所有现有路由、API 路径、请求参数、响应字段、静态数据回退和业务状态继续沿用。前端只负责显示后端返回值，不重算匹配分、置信度或统计值。

冻结的 `standard*_v1.xlsx`、真实 JD、简历、岗位图谱和动态演化数据不修改、不移动、不重命名。改版前后的 SHA-256 必须逐项一致。

## 状态与错误处理

API 页面保留或补齐：加载中、无数据、失败、重试、按钮禁用和表单校验。错误提示使用普通用户语言，同时避免吞掉诊断信息。静态回退可说明“暂时无法连接服务，正在展示最近可用数据”，但不暴露部署或实现细节。

## 验证

1. 改版前记录前端测试、生产构建和冻结文件哈希。
2. 改版后重新运行 `npm test`、`npm run build` 和适用的后端回归测试。
3. 浏览器逐页检查八条路由、主要交互、控制台错误和 Evidence 入口。
4. 在 1920×1080、1366×768 和约 768px 宽度检查布局与溢出。
5. 输出八页改版后截图、修改文件清单、测试退出码、哈希对照、已知限制与人工确认项。

## 完成标准

八页统一为白底商业化风格；无无关开发者文案；所有原有功能、按钮、筛选、Evidence、API 与真实数据保持可用；生产构建成功；冻结文件哈希一致；目标分辨率无明显布局溢出。
