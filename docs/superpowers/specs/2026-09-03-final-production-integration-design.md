# 最终生产系统选择性集成设计

## 目标与边界

在现有 Render 项目和现有 `main` 分支内完成最终集成：保留当前白底商业化界面与白底期间新增数据，修复简历文档抽取、简历字段映射、技能 Evidence、图谱/演化实时读取，并验证八个核心页面。不得创建平行系统、Vercel 项目或新 Render 项目，也不得用历史提交整体覆盖工作区。

## 版本与数据保护

`21d7cf9` 是白底改造前最后一个稳定功能提交；`3b8aa89` 发布白底 UI 并接入 supplemental JD v3；`a0ac180` 增加分析接口瞬时断线重试。集成采用 Git diff、函数级修复与兼容字段扩展，不回滚任何完整提交。

修改前后分别生成 `reports/pre_final_integration_data_baseline.json` 和 `reports/post_final_integration_data_baseline.json`。基线记录正式 JD、标准岗位、冻结/运行时技能、图谱节点/关系、新岗位候选、测试简历、多源 Evidence 数量，以及所有核心数据文件的 SHA-256。若修改后任一受保护数量减少或文件哈希变化，停止提交与部署。

## Resume 数据流

文件上传继续使用现有 `/api/resume/extract`，支持 PDF、DOCX、TXT，并只在内存解析。文档 Adapter 从原文提取姓名、联系方式、目标岗位、学历、专业、明确工作年限、工作经历、项目经历和技能区；章节识别必须在遇到任意新标题时停止，避免整份简历串入同一字段。

工作经验优先采用原文明示的年限，兼容 `1年`、`1 年`、`工作经验：1年`、`1年工作经验`、`1 年（项目实践与实习经历）`。未明示但存在正式工作或实习日期范围时才可近似推算并标记来源；普通学生项目不得计为工作经验。

`/api/resume/parse` 保持既有请求字段兼容，并以新增可选字段扩展响应。前端保留白底工作台，在结果区展示基本信息、工作经历、项目经历、岗位技能覆盖与 Evidence。

## 技能 Evidence 与能力画像

技能只从用户简历字段中抽取。每条 Evidence 截取包含命中技能的最小句子或列表项，并保留相对原字段的命中偏移；不得把整个项目段复制给每个技能。

Evidence 强度规则：实际行为词与项目/工作上下文为强；技能清单中的明确掌握/熟悉或单独列出为中；了解、学习、接触、简单提及为弱。否定、计划学习、他人经历和冲突陈述不计为可靠覆盖。

现有 `0.98/0.93/0.90` 是规则匹配强度，不是熟练度。简历页不显示百分比，改为强/中/弱 Evidence，并保留机器可读的识别置信度及其语义字段以维持 API 兼容。

能力覆盖率定义为“具有可靠 Evidence 的岗位要求技能数 / 当前岗位要求技能总数”。页面分别展示已覆盖核心技能、已覆盖加分技能、弱 Evidence 技能和缺失技能；不得称为录用、Offer 或胜任概率。

## 实时 API 与 fallback

图谱和动态演化继续优先调用同源正式 API。GET 请求对网络断开和 502/503/504 做有限次数、带间隔重试，以覆盖 Render 冷启动；只有重试耗尽或响应无效时才读取已打包的静态正式结果。页面切换岗位时清理旧错误状态，服务恢复后重新获取实时数据。

动态演化同时说明系统总 JD、当前岗位 JD 和演化有效样本。AI Agent 开发工程师的 12 条来源于标准化 JD 中该岗位的真实子集，不为追求总数一致而修改。

## 验证与部署

新增后端测试覆盖字段抽取、工作年限格式、最小 Evidence、强弱分级、无虚构技能与岗位覆盖；新增前端测试覆盖 GET 冷启动重试、真实失败 fallback 与百分比移除。运行全部 Python 与前端测试、TypeScript/Vite 构建和现有系统 QA。

本地验证八个路由与关键 API 后检查 Git diff 和数据基线，提交并推送现有 `origin/main`，等待现有 Render 自动部署。最后实际访问生产首页、`/graph`、`/resume-parse`、演化页面及八个核心 API，确认构建版本与最新提交一致。
