# 第三阶段：正式标准化数据报告

> 本阶段以人工审核结果为最高优先级，并结合真实 JD 正文完成可可靠判断的岗位复核。所有结果均为新文件；5 个原始 Excel、人工审核文件和第二阶段文件均未修改或覆盖。

## 一、本阶段做了什么

1. 读取“第二阶段人工审核完成版.xlsx”中的岗位、技能和简历审核结果。
2. 对 39 条“需结合 JD 正文确认”的岗位读取工作职责、必备技能、加分技能、企业信息等证据；可靠者确认，证据不足者继续标记人工确认。
3. 建立正式岗位名称映射、稳定编号的标准技能库、标准化 JD 数据和标准化测试简历。
4. 保留原始字段、原始行号和判断依据，保证每条结果可回溯。
5. 执行编号、别名、岗位名称、空值和原始文件哈希一致性检查。

## 二、创建的正式数据文件

- standard_job_title_mapping_v1.xlsx：191 条 JD 岗位映射。
- standard_skill_dictionary_v1.xlsx：82 个标准技能、146 条技能别名映射。
- standardized_jd_dataset_v1.xlsx：191 条标准化 JD，保留原始文本。
- standardized_resume_testset_v1.xlsx：27 条去重后的正式测试简历。

## 三、岗位名称标准化结果

- 最终标准岗位名称：117 个。
- 75 条原未匹配岗位中，按人工审核直接确认：36 条。
- 根据 JD 正文新增确认：27 条。
- 仍需人工确认：12 条。

仍需人工确认的岗位：JD-067（AI数据工程师）、JD-081（自动驾驶感知测试开发工程师）、JD-084（AI评测）、JD-085（大模型评估产品经理）、JD-088（AI模型评估）、JD-166（具身智能数据服务PDSA（J99380））、JD-167（具身智能数据服务解决方案与项目经理（J102453））、JD-176（大模型安全运维工程师）、JD-178（攻防红队工程师）、JD-181（AI与云安全工程师）、JD-184（安全专家（AI方向））、JD-185（AI安全专家）。这些记录没有被强制映射，正式 JD 表中的标准岗位名称保持为空，并保留待确认候选名称和理由。

## 四、标准技能库结果

- 标准技能：82 个。
- 技能别名映射：146 条。
- 经人工批准的一对多拆分映射：14 条。
- skill_id 使用稳定顺序编号；以后更新时应优先读取本 V1 文件，保留已有编号，只为新增技能追加编号。

人工规则已落实：MCP Server 与 MCP 协议分开；C/C++ 按语义拆分；Docker/Kubernetes、Linux/Shell、JavaScript/TypeScript 分开；RAG、Embedding、向量数据库、重排序不合并；Agent Runtime、Agent Loop、Agent Harness 只按原文实际出现内容建立。

## 八、是否满足进入 JD 自动解析模块的条件

建议**有条件进入下一阶段**：现在可以开始 JD 自动解析模块的原型设计和字段抽取测试，因为正式字段、标准岗位、技能库和追溯链已经建立。但必须在训练、评测或知识图谱正式入库时排除上述 12 条未确认岗位，或把它们作为“待审核”状态处理。

下一阶段建议只做 JD Parser：输入一条原始 JD，输出结构化字段、标准岗位候选、标准技能及证据位置，并保留人工复核入口；暂不同时开发知识图谱、前端或人岗匹配。
